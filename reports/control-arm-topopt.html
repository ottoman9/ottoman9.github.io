Section 5: Load Case Derivation and Analytical Validation (v3)

Architecture note: the part modelled is a double-wishbone front upper control arm, spring mounted on the lower arm, per the stated design intent. Vehicle-class parameters (mass, wheelbase, track, tyre size) are taken from the Golf R as a representative reference vehicle; the real Mk7 Golf R front axle is MacPherson strut, not double wishbone, so this is a double-wishbone front corner sized to Golf-R-class parameters, not a literal model of the production part.

5.1 Methodology for Load Case Selection

The analysis adopts the standardized acceleration load cases of Nassar et al. (2025), in which suspension loads are expressed as multiples of gravitational acceleration (g) acting at the tire contact patch. All three published cases, Bumping, Cornering, and Brake-in-Turn, are evaluated, rather than the single Brake-in-Turn case of the original study revision. This is required for the downstream topology optimization: a shape optimized against one load direction is unprotected in every direction that case does not exercise.

5.2 Load Path Rationale: Why the UCA Sees What It Sees

The UCA pivots freely about its bushing axis. A hinge cannot react a force that merely rotates it; vertical wheel travel therefore swings the arm rather than loading it, and the vertical load path runs tire to knuckle to lower ball joint to lower control arm to coil spring to body. The UCA can only be loaded in the directions its kinematics refuse: longitudinal forces from road friction and lateral forces from cornering, both reacted as a force couple across the knuckle between the upper and lower ball joints.

Consequently the UCA carries only an assumed 500 N vertical residual (bushing friction, ball joint articulation drag, and arm angularity effects), while the braking and cornering components dominate the design loads.

5.4a Free Body: The Longitudinal Force Correction

The original (v2) derivation used the tire rolling radius R_t = 0.324 m as the moment arm for the longitudinal (braking) force reacted by the UCA. This is wrong for an outboard, knuckle-mounted brake.

The caliper is bolted to the knuckle, not to the control arm. Brake torque is generated and reacted entirely within the free body outboard of the ball joints (caliper against disc against knuckle); it never crosses the ball joints and is never an external moment on the UCA. The only external longitudinal force acting on that free body is road friction at the tire contact patch. That force acts at ground level, a height h_LBJ = 0.150 m below the lower ball joint, not R_t = 0.324 m below it.

This is exactly the arm the document already used, correctly, for the lateral force in the same case. The fix makes the longitudinal and lateral treatments consistent:

F_UCA,x = F_road,x x h_LBJ / h_k     (corrected; was F_road,x x R_t / h_k)

5.4 Case 1: Brake-in-Turn (P = 1.0 g, S = 0.75 g, B = 0.75 g)

Under hard braking while cornering, the body's inertia at the centre of gravity height h_cg produces two simultaneous weight transfers onto the outboard front wheel: a longitudinal transfer (nose-dive, over the wheelbase L) from the braking component, and a lateral transfer (roll, over the track t) from the lateral component. Nassar Table 4 specifies both at 0.75 g for this case, so both transfers must be evaluated at 0.75 g, not at the 1.2 g tire-adhesion envelope used for the longitudinal term in the superseded version, and the lateral transfer (previously omitted entirely) is now included using the same structural pattern Case 2 already uses for its own lateral transfer.

dW_long = m . (0.75 g) . h_cg / L / 2
        = 2,060 x 7.3575 x 0.53 / 2.63 / 2 = 1,527.2 N

dW_lat  = W_front . 0.75 . h_cg / t
        = 12,125.2 x 0.75 x 0.53 / 1.54    = 3,129.7 N

N_wheel = W_corner + dW_long + dW_lat
        = 6,062.6 + 1,527.2 + 3,129.7      = 10,719.5 N

Tire force generation is friction-limited: the tire can push against the road by at most its instantaneous vertical load times the utilized friction fraction. Both axes share the same 0.75 g multiplier in this case, so one F_road value applies to both:

F_road = 0.75 x N_wheel = 0.75 x 10,719.5 = 8,039.6 N   (per axis)

Plausibility check (friction circle, not part of the transfer calculation itself): the resultant demand is sqrt(0.75^2 + 0.75^2) = 1.06 g, which lies inside an assumed 1.2 g tire-road adhesion limit for a typical passenger tire. Braking and cornering share, and cannot simultaneously saturate, the available grip.

The road force acts at ground level; the UCA reacts it as one member of a force couple across the knuckle (moment balance about the lower ball joint). Per the free body in Section 5.4a, both the braking force and the lateral force now act through the same arm, h_LBJ:

F_UCA,x = F_road x h_LBJ / h_k = 8,039.6 x 0.150 / 0.250 = 4,823.8 N
F_UCA,z = F_road x h_LBJ / h_k = 8,039.6 x 0.150 / 0.250 = 4,823.8 N

(F_UCA,x and F_UCA,z are equal because B and S are both 0.75 g in Table 4 for this case, and both now use the same arm and the same F_road.)

Applying the k_d = 1.6 abuse factor:

F_x = 4,823.8 x 1.6 = 7,718.0 N (rearward)
F_z = 4,823.8 x 1.6 = 7,718.0 N (lateral)
F_y = 1.0 x F_res    =   500.0 N (residual, P = 1.0 g)

5.5 Case 2: Cornering (P = 1.0 g, S = 1.25 g, B = 0)

Unchanged by this revision; reproduced here for the full-chain record.

In steady cornering the tires pull the car toward the turn centre at road level while the body's inertia acts outward at h_cg. This force pair rolls the body onto the outboard wheels: the outer wheel gains the load the inner wheel loses, separated by the track width t. Balancing the roll moment against the load-transfer moment for the front axle:

dW_lat  = W_front x 1.25 x h_cg / t
        = 12,125.2 x 1.25 x 0.53 / 1.54 = 5,216.2 N

N_outer = 6,062.6 + 5,216.2 = 11,278.8 N

Plausibility check: the inner wheel drops to 6,062.6 - 5,216.2 = 846.4 N, near lift-off, which is the expected condition at a 1.25 g lateral limit and confirms the transfer magnitude is physical.

F_road,z = 1.25 x N_outer = 1.25 x 11,278.8 = 14,098.5 N

F_UCA,z = 14,098.5 x 0.150 / 0.250 = 8,459.1 N
F_z     = 8,459.1 x 1.6            = 13,534.5 N (lateral)

No braking component exists in this case: F_x = 0. F_y = 1.0 x F_res = 500 N (residual, P = 1.0 g).

5.6 Case 3: Bumping (P = 2.0 g, S = 0, B = 0)

The applied load is unchanged by this revision (F_y = 1,000 N). What changes is the framing: the scrub-radius finding in Section 5.8 below shows this case is no longer near-null once a real, if excluded, load path is considered.

A 2.0 g vertical bump doubles the static wheel load (no longitudinal transfer applies; the vehicle is not decelerating). Per Section 5.2, this vertical load bypasses the UCA almost entirely via the LCA and spring; the arm pivots with the suspension travel rather than resisting it. The UCA input scales only the residual:

F_y = 2.0 x F_res = 2.0 x 500 = 1,000 N

This case is retained in the analysis set because it demonstrates, rather than asserts, that the UCA's direct vertical load path is small. It does not, on its own, demonstrate that the corner is negligible under bump: see the scrub-radius finding below, which shows a real lateral load path exists at this event that is not captured by the 500 N residual model.

5.8 Stated Assumptions and Limitations

  1. Front/rear split (60/40), h_cg (0.53 m), and track (1.54 m) are assumed from typical published data for this vehicle class, not measured.
  2. Roll stiffness distribution is neglected; lateral weight transfer is apportioned to the front axle by static axle load share. Real anti-roll bar tuning may load the front outer wheel further.
  3. The 500 N vertical residual on the UCA is an engineering assumption (Section 5.2). A sensitivity solve (0 N vs 1,000 N) is planned to demonstrate result insensitivity.
  4. Single-corner idealization: the outboard corner is assumed to carry the full grip demand. Conservative for the arm under design.
  5. Loads are static "snapshot" peaks at the worst dynamic instant; no inertia relief or transient effects are modeled. The k_d = 1.6 factor covers dynamic exceedances (ABS pulsation, mid-event road irregularity).
  6. Bushing compliance is idealized as rigid (encastre at RP-2/RP-3); bore-level load distribution is smoothed by distributing couplings.
  7. Traction (halfshaft torque), excluded from the load set. Halfshaft torque reaction is carried by the differential case, bolted to the subframe, not by the UCA: the same internal-reaction argument as the corrected braking free body in Section 5.4a. As a bounding check only (this force never actually reaches the arm), at 0.6 g with an even (50/50) AWD front/rear torque split, the front-wheel tractive force is 3,031 N; referred through the CV-joint-to-lower-ball-joint height offset (R_t - h_LBJ = 0.174 m) against h_LBJ, this bounds to approximately 3,516 N, well below both Case 1's peak (7,718 N) and Case 2's peak (13,535 N). It does not govern and is not added to the formal load set.
  8. Scrub radius, excluded from the load set but no longer treated as negligible. An assumed 50 mm scrub radius (typical hot hatch, not measured) under the 2.0 g bump case (Case 3) offsets the tire's vertical reaction line from the kingpin axis. Using the full 2g corner vertical load (12,125 N) and the same ball-joint-couple free body used throughout this section: F_scrub = 12,125 N x 0.050 m / 0.250 m = 2,425 N of lateral load into the arm. This is more than double Case 3's documented 1,000 N residual. Case 3 (Bumping) must no longer be described as a "near-null verification case": the scrub-radius path alone puts a non-trivial lateral load into the arm under this event. The scrub term itself remains excluded from the formal load set (it is a limitation, not an applied load, pending a proper scrub-radius geometry value from the actual knuckle/steering design), but its magnitude is shown here explicitly so the "near-null" framing is retracted with a number attached, not just asserted away.

The text this section carried until 2026-08-03 claimed the elastic and plasticity-enabled runs were "identical within 0.04% on a plasticity-enabled run" and that removing plasticity bought a "60× slower stiffness-matrix path." Neither figure is what is on disk. Re-checked directly against the existing (un-rerun; this is a historical method-validation independent of the Section 5 v2 load correction) logs:

Difference: (139.37 − 139.2) / 139.2 = 0.12% (0.14% using the 1-decimal figures 139.4 vs 139.2). This is a peak-stress comparison, not a strain-energy/objective comparison - no such objective comparison exists in the record, and the document should not have claimed one.
  • Wall-clock cost. Per-design-cycle FE-solve time, read directly from the tosca_driver timestamps in uca_topopt_stdout.log (plasticity run, VF 0.40) and uca_topopt_v40_stdout.log (elastic surrogate, VF 0.40, same design, same old loads): the first design cycle (cycle 0, full/near-full density "blank," the most expensive cycle since the stiffness matrix is factorized from scratch and the plastic material first has to iterate a return-mapping solution) took 353 s plastic vs 36 s elastic - a 9.8× ratio, close to the record's prior informal "about 335 s / about 35 s, ≈9.6×" note. The defense brief's Q5 answer ("60× slower... in the optimization loop") is not supported by any log on disk and should be corrected there as well (out of scope for this document per the brief's step 8; flagged for whoever owns that file).

Method statement. Every number in this table, on both the baseline and all three optimized designs, is a raw, unfiltered, kept-element (SIMP density ρ > 0.5) maximum: masked straight from the full element/node arrays, no additional filtering, exactly as verify_v25.py established. The old interior-filter method in peak_interior.py (drop every kept element that shares a node with a killed element) is retired: it excludes the entire free surface of the optimized part, which is exactly where an optimized shape's peak stress lives. peak_interior.py is kept in the pipeline archive as a record of the retired method; none of its output is used here or anywhere in this pass.

Mass method. Two independent computations per design, and they agree: (1) sum of each design's own kept-element volumes (C3D10 corner-node tetrahedra, taken directly from that design's own final-cycle odb geometry) × density 7.85×10⁻⁹ t/mm³ - this is the number in the table above; (2) sanity cross-check against the historical (2026-08-03, different session, different load case, independently derived) mass figures for the same three volume fractions - 9.2 / 7.1 / 5.8 kg - which this pass's fresh geometry-based figures (9.199 / 7.143 / 5.809 kg) match to within 1% at every volume fraction, a meaningful agreement since design topology is governed primarily by the volume-fraction target and overall load-path character, not by the small shift in load magnitudes. (A planned third check - parsing ASSEMBLY_DESIGN_ELEMS / ASSEMBLY_FROZEN_ELEMS straight out of the .inp and re-summing against the independently-meshed baseline odb - did not reconcile: Tosca's internal element numbering in the density files does not match the source model's Abaqus element labels, so that specific cross-check was abandoned rather than reported as agreeing when it does not measure the same thing.)

Governing-case inversion (Section 5 v2 finding), confirmed in these results. Cornering governs every single design point in the new table above, baseline through VF 0.15 - not Brake-in-Turn, which governed every point in the old (superseded) table. This is the direct numeric consequence of the Section 5 v2 correction: Brake-in-Turn's peak load component dropped from 13,229 N to 7,718 N (the moment-arm and lateral-transfer fix), while Cornering's Fz = 13,534.5 N is unchanged. At the recommended VF 0.25 point, Brake-in-Turn is now 99.23 MPa against Cornering's 116.96 MPa - Cornering leads by 18%, not the other way round.

Knee-point recommendation: holds, with more margin than before. Every design point in the new table has a higher FoS and a lower deflection than the corresponding point in the old (superseded) table - a direct result of Brake-in-Turn's overall reduction. The shape of the trade curve is unchanged: mass falls cheaply from baseline through VF 0.40 to VF 0.25 (a 59% mass cut costs only 7% more governing stress), then the cost per kilogram saved jumps sharply from VF 0.25 to VF 0.15 (a further 19% mass cut costs 31% more governing stress and 62% more deflection). That accelerating cost is still the knee, and it still sits between VF 0.25 and VF 0.15.

Independent hand-calc validation, specific to the VF 0.25 design. The defense brief's Q9 already carries an honest hand beam-calc cross-check that failed by 16.2x against the un-optimized blank, for a stated reason: that blank is a bulky multi-load-path solid, not a discrete beam. A second hand-calc, run against the VF 0.25 topology itself, a genuine two-strut structure with slender beam-like members, gives beam theory a real member to work with: sigma_hand comes out to 38.70 to 77.39 MPa (two load-sharing bounds, since the two struts meet the ball joint through a single merged region with no determinate split) against an FE value of 43.95 MPa at the same, geometry-frozen section, ratios of 0.88 and 1.76, a genuine PASS at both bounds. See Q9 in P2_DEFENSE_BRIEF.md for the full account and strut_handcalc_v25.py (pipeline_20260802) for the derivation.

Unlike the old table, VF 0.15 no longer fails either check under the new loads (FoS 3.65 is still comfortably inside the 1.5-2.0 target band with margin to spare, and 0.76 mm deflection no longer approaches 1 mm) - so VF 0.15 is a legitimate design if maximum mass saving is the priority. VF 0.25 remains the recommendation here because it sits at the point before the disproportionate stress/deflection cost begins, preserving margin against the assumptions in Section 5.8 (unmeasured CG height, track, scrub radius, roll distribution) - not because the old numbers forced it.

The optimized topology is consistent across all three volume fractions: two tapered struts from the bushing tubes converging into a hollowed shell around the outboard ball joint, matching the pre-correction result and the Section 6.3 internal stress audit's load-path prediction - the corrected loads changed the numbers, not the shape of the answer.

Every number below comes from running fatigue_v2.py (plain CPython 3.11, no Abaqus dependency), with its full stdout captured to fatigue_v2_log.txt. The script consumes only the verified, already-solved Section 6B.2 stress numbers as literal inputs; it does not re-run, re-mesh, or re-solve any FE model.

Governing input. VF 0.25 (recommended design), Cornering case, raw unfiltered kept-element peak = 116.96 MPa. This is a factored FE result: the SAE k_d = 1.6 abuse factor is already baked into the applied load (Section 5.4/5.7 of P2_Section5_LoadCases.md). No interior filtering is applied anywhere in this assessment; that method is retired project-wide.

1. UTS derivation. The deck's hardening table (SAE 4130) caps at 760 MPa true stress, 15% true plastic strain. That is an upper bound on true stress at this hardening-table extent, not a usable engineering UTS: true stress keeps climbing with necking-driven area reduction well past the real engineering ultimate point, so 760 MPa was not carried forward. The table's 0-plastic-strain point, 560 MPa, is the deck's modeled yield strength Sy.

Two standard, citable SAE/AISI 4130 conditions were checked against Sy = 560 MPa, rather than importing 731 MPa unreconciled:

Candidate Condition Source Published Sy Published Su Gap from deck Sy = 560 MPa
1 Normalized at 870 C (1600 F) MatWeb / ASM Alloy Center Database, datasheet "AISI 4130 Steel, normalized at 870C (1600F)" (matguid e1ccebe90cf94502b35c2a4745f63593), fetched 2026-08-10 435 MPa 670 MPa 28.7% (deck above)
2 Quenched and tempered, low-strength end of the standard tempering range MatWeb quenched-and-tempered AISI 4130 datasheet family, range summarized via modulusmetal.com, fetched 2026-08-10 690 MPa 862 MPa 18.8% (deck below)

The commonly quoted "normalized SAE 4130, Sy 460 MPa, Su 731 MPa" figure was also checked as the brief's starting reference point. It is a different, less specific citation than Candidate 1, and it is the exact number the original (2026-08-03) section imported unreconciled; it is recorded here only as the reference point, not carried forward.

Neither candidate reconciles with the deck's Sy = 560 MPa within 10%. Candidate 2 is the numerically closer condition (18.8% gap versus 28.7% for Candidate 1), but per this rebuild's rule, the outcome when no condition reconciles is to carry forward the lower, more conservative, of the two candidate UTS values rather than the numerically closer one:

UTS carried forward = 670 MPa (Candidate 1, normalized, MatWeb/ASM), because it is lower than Candidate 2's 862 MPa. This avoids crediting the material with more strength than the deck's own hardening table supports. This choice, and the 10% reconciliation test itself, are stated plainly as judgment calls made in the absence of a clean match, not as a resolved citation.

2. Endurance limit (Shigley Marin equation). Se' = 0.5 x UTS = 335.0 MPa. The 0.5 factor is valid only for UTS below about 1400 MPa (Shigley's Mechanical Engineering Design, Budynas and Nisbett); 670 MPa clears this comfortably.

Every Marin factor, with its citation and reasoning:

Factor Value(s) Reason
ka, surface Machined: 0.804. As-forged: 0.419 ka = a x Su^b, Su in MPa (Shigley Table 6-2). Machined/cold-drawn: a=4.51, b=-0.265. As-forged: a=272, b=-0.995. As-forged, not hot-rolled, is used as the rough-surface route: Shigley's table has no separate "cast" row, and as-forged is the roughest tabulated category, the closest standard analog to an unmachined cast surface; hot-rolled is a distinct, smoother category for rolled bar stock, not a cast or forged blank. Manufacturing route is still open project-wide, so both routes are carried forward.
kb, size 0.806 (conservative, used); 0.938 (smaller estimate, shown only, not used) Rotating-beam-equivalent-diameter approach for a non-circular, non-rotating section (Shigley Section 6-9), a known approximation since the arm is not a rotating shaft. Exact local strut geometry at the governing location is unmeasured (out of scope); two labeled engineering estimates were built from the bounding box (X 339.88 mm, Y 67.52 mm, Z 326.34 mm, geom_dims_log2.txt) and the 6 mm frozen-collar minimum member size: a "small" estimate (Y span x sqrt(VF 0.25), then an extra 0.5 conservative shrink toward the necked-down local section, giving 16.88 mm, well above the 6 mm floor) and a "large" estimate (the raw Y span, 67.52 mm). Per Shigley's own kb formula, kb decreases as diameter increases, so the smaller estimate actually gives the larger, less conservative kb; this corrects a naive "smaller is always conservative" framing. The larger estimate is carried forward for kb because it gives the lower, more conservative Se. Both diameters were converted via Shigley's non-circular-section formula d_e = 0.808 x sqrt(h x b), assuming a square local section h = b (no independent width data), before applying the kb formula.

kd, temperature 1.0 Operating near room temperature, no elevated-temperature service in this application; Shigley's default at or below room temperature.

Kf, notch Not applied The 116.96 MPa Cornering figure is a raw, unfiltered, kept-element FE maximum: it already includes the real geometric stress concentration from the fillets and local mesh at the governing location, it is not a nominal section stress. Applying a textbook Kt/Kf on top would double count that same geometric effect. Resulting endurance limits, both surface routes:

  • Se (machined) = 0.804 x 0.806 x 1.0 x 1.0 x 0.753 x 335.0 = 163.46 MPa
  • Se (as-forged) = 0.419 x 0.806 x 1.0 x 1.0 x 0.753 x 335.0 = 85.26 MPa

3. Service-load stress amplitude. The 116.96 MPa Cornering peak is a factored-load result (k_d = 1.6 already applied). A genuine fatigue amplitude needs the service-load stress, and the model is confirmed linear elastic at this load level (PEEQ = 0 in all three load steps, Section 6B.1/6B.3), so stress scales linearly with load: dividing the factored peak by k_d recovers the unfactored service peak exactly, with no approximation.

  • Step 1: service peak stress = 116.96 / 1.6 = 73.10 MPa
  • Step 2: the cycle is defined as R = 0 (service loads pulsate from zero to this peak and back to zero, tension-release repeated loading, not fully reversed): sigma_max = 73.10 MPa, sigma_min = 0 MPa, sigma_mean = sigma_amp = sigma_max / 2 = 36.55 MPa

4. Modified Goodman margin, both routes, equal prominence. Goodman line: sigma_amp / Se + sigma_mean / Su = 1 / n_f.

Route Se [MPa] sigma_amp / Se sigma_mean / Su Sum n_f Result
Machined 163.46 0.2236 0.0546 0.2782 3.595 Survives (n_f > 1)
As-forged 85.26 0.4287 0.0546 0.4832 2.069 Survives (n_f > 1)

Both routes pass. The as-forged route carries roughly half the margin of the machined route (n_f 2.069 versus 3.595), which is expected given the as-forged ka penalty, but it does not fail: n_f stays above 1 on both routes at the governing Cornering event.

5. Duty cycle and Miner argument. The assumed 300,000 km spectrum is carried forward unchanged: 10^4 brake-in-turn events, 10^5 cornering events, 10^6 bump events, all R = 0 pulsating cycles. This spectrum is an assumption still pending final confirmation, not an OEM-measured duty cycle.

For the governing Cornering event class (sigma_amp = 36.55 MPa) at both routes: sigma_amp is below Se on both routes (163.46 MPa machined, 85.26 MPa as-forged), so in the classical S-N infinite-life idealization this event class contributes zero cycles to a Miner damage sum on either route. No S-N slope was ever defined for this project, so no finite N is fabricated here; the zero-damage statement is the classical idealization's own conclusion, stated plainly rather than dressed up with a manufactured number.

What this fatigue analysis is not. No fe-safe run has been performed; this is a hand (scripted) stress-life calculation only. No multiaxial stress treatment was applied; the FE peak is a single scalar von Mises value, not a full multiaxial fatigue criterion. No measured, vehicle-instrumented load spectrum exists; the 300,000 km duty cycle above is an assumption pending sign-off, not measured data. These gaps are stated here so they are not mistaken for a completed durability certification.
